# Needs announcement

The purpose of announcing tickets is clear communication and coordiation. 

- Is the change in a shared repository where communication even makes sense?
- Is this a release or just a deploy? (We do not need to communicate stuff we're deploying behind a release flag).
- Is it a game-changer for customers/staff (decides the target channel)?
- Is it clear and to the point?
- Is it going out to customers or internally?
- Is it sensitive enough to warrant Rasmus' attention?
- Does it sound like Rasmus?
- Check the date: is it still worth sending, or would it come across as old news?
- Does it require numbers? (For example improved error percentages)
