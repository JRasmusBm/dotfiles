# Needs announcement

The purpose of announcing tickets is clear communication and coordination.
Then send or don't. A draft written before this step is not an
answer: re-decide its channel and audience too.

- Is it still unsettled? Is the ticket still in Needs announcement
  (Rasmus moving it on, e.g. to Done, means he decided it needed no
  post), and has nobody announced it yet, in the channel or from a
  related ticket?
- Is the change in a shared repository where communication even makes sense?
- Has it reached the people it's for? An internal fix is for the team,
  so it has. A customer feature still hidden from customers by a
  release flag, an experiment, a pending run or a missing entry point
  hasn't, even if staff can see it.
- Is it a game-changer for customers/staff, and which channel does that
  make it?
- Who reads it: customers or the team? Is it sensitive enough to warrant
  Rasmus' attention?
- Who is waiting to hear about this, and where? (The thread it came
  from, an earlier post that promised it.) Read the room there
  first: what did we promise? Is this a useful notification? Would
  it be more helpful to merge it with other changes, and is this the
  last item in the batch that should post, or should we skip in
  favor of a later one? A sub-issue with open siblings: the parent
  owns the post, so tell its agent what went live instead.
- Would Rasmus send it as written: clear, to the point, in his voice?
- Check the date: is it still worth sending, or would it come across as old news?
- Does it require numbers? (For example improved error percentages)
